# Дата-квест Ники — спецификация для Claude Code

Персональный мини-курс для Ники (Python backend → Data Engineer): дорожная карта, материалы,
мини-тесты, симулятор техсобеса, геймификация с реальными наградами от мужа.
Хостинг — GitHub Pages, сайт должен работать без запущенного компьютера.

Контент курса уже собран в `content/roadmap.json`. Не переписывай его — только читай и расширяй.

---

## 1. Стек (решение принято, не менять без причины)

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite + React + TypeScript | статическая сборка в `dist/`, без сервера |
| Роутинг | `HashRouter` (react-router) | GitHub Pages не умеет SPA-фолбэк, hash-роуты работают без 404.html |
| Стили | обычный CSS / CSS Modules, без UI-кита | «типичный курс», минимальный дизайн |
| Контент | `content/roadmap.json`, импорт на этапе сборки | правится через PR, без админки |
| Прогресс (этап 1) | `localStorage` + экспорт/импорт JSON | ноль инфраструктуры |
| Прогресс (этап 2) | Supabase (free tier): Auth по email-ссылке + таблица `progress` | синхронизация между устройствами и «пульт мужа» |
| Деплой | GitHub Actions → `actions/deploy-pages` | push в main = обновление сайта |

`vite.config.ts`: `base: '/<имя-репозитория>/'`.

## 2. Страницы

- **Шапка на всех страницах**: навигация и огонёк серии с числом (серый, пока сегодня не активен; яркий,
  когда активен). Клик по огоньку — панель: лента недели Пн–Вс (активен / заморожен / пропущен / сегодня),
  число заморозок, лучшая серия, календарь месяца. После 20:00, если сегодня не активен и серия ≥1, под
  шапкой баннер «Серия под угрозой: остался 1 квест». Push-уведомлений нет (статический Pages без сервера).
- `#/` — **Карта**. Сверху статус-бар: ранг, уровень, полоска XP, серия дней, «сегодня X/3 тем».
  Карточки «Продолжить» (следующая непройденная тема), «Квест дня» (X из 3) и «На повторение»
  (темы, пройденные ≥5 дней назад). Ниже извилистая карта: 7 блоков по порядку обучения (это и есть
  последовательность), темы-узлы со статусом, боссы после своих блоков.
- `#/daily` — **Ежедневный квест** (по локальной дате устройства). Один квест в день из трёх заданий:
  1. **Ежедневный тест** — 5 вопросов из мини-тестов пройденных тем, сдан при ≥4/5, попыток сколько
     угодно, засчитывается лучший результат дня. Если в пуле меньше 5 вопросов — берутся все, сдан при ≥80%.
  2. **Два побочных задания** из пула: `new-topic` «Пройди новую тему», `materials-2` «Открой 2 материала»,
     `perfect` «Сдай мини-тест на 3/3», `note` «Напиши заметку к теме (от 50 символов)»,
     `review` «Повтори тему, пройденную 3+ дня назад». `new-topic` не выбирается, когда всё пройдено;
     `review` — когда нет темы старше 3 дней.
  Все три выполнены → **сундук дня** (экран открытия + XP). Пока нет ни одной пройденной темы, квест закрыт:
  «Пройди первую тему, чтобы открыть ежедневные квесты».
  Подбор детерминирован по дате: seed = хеш `YYYY-MM-DD`, ГПСЧ mulberry32. Пул — вопросы `quiz` пройденных
  тем; вес темы `1 + дней с lastReviewAt (или doneAt)`, ×2 если `best < 3`. 5 разных вопросов, не больше 2 из
  одной темы (если пул позволяет), без вчерашних вопросов (если без них остаётся ≥5). Квест **закрепляется
  за днём** при первом показе (`days[d].quest.questionIds`, `days[d].tasks`), чтобы прогресс в течение дня
  его не менял. Тема, где все вопросы теста отвечены верно, получает `lastReviewAt = сейчас` (уходит из
  «На повторение»; это не повторение и XP за него не даёт).
  **Реванш**: если серия ≥3 сгорела из-за ровно одного пропущенного дня, в течение следующего дня доступен
  двойной тест (10 вопросов, сдан при ≥8/10, одна попытка). Сдан — пропущенный день `frozen` + `revenge`,
  серия восстановлена. Реванш не засчитывает сегодняшний день.
- `#/topic/:id` — **Тема**: «что повторить / что изучить» (`recap`), материалы (`materials`, клик = отметка
  «открыто»), личные заметки (textarea, автосохранение), мини-тест из 3 вопросов.
  Материалы сгруппировать по `type` (статьи, видео, документация, практика, книги); у материалов с
  `lang: "en"` — метка «EN». Русские показывать первыми внутри группы. Ссылки открывать в новой вкладке.
  Тема засчитывается при ≥2/3 правильных. Повторная сдача после 3+ дней = «повторение» (+XP).
- `#/exam` — **Боссы (симулятор собеседования)**, список в `exams`. Прохождение: N вопросов с выбором
  из пула блоков (случайно, без повторов), видимый таймер, затем открытые вопросы из `open_questions`
  с самооценкой: «показать эталон» → «знала / частично / не знала». Сдано, если тестовая часть ≥80%.
  `final` заблокирован, пока не сданы остальные три.
- `#/achievements` — **Ачивки**: сетка значков (закрытые — серые с условием), у открытых дата и награда
  с кнопкой «Забрать». Статусы награды: доступна → запрошена → выдана.
- `#/settings` — дневная цель (по умолчанию 3 темы), экспорт/импорт прогресса JSON, сброс.
- (этап 2) `#/admin` — **Пульт мужа**: её XP, темы, история боссов, запрошенные награды с кнопкой «Выдано»,
  редактирование текстов наград.

Варианты ответов в тестах **перемешивать при каждом показе**: в JSON правильный ответ всегда первый (`options[0]`).
После проверки показывать `explain` к каждому вопросу.

## 3. Модель прогресса

```ts
type DayStats = {
  topics: number;          // новые темы
  reviews: number;         // повторения тем
  materials: number;       // открыто материалов
  perfectQuizzes: number;  // мини-тестов 3/3
  notes: number;           // тем, где заметка впервые стала ≥50 символов
  quest?: { best: number; total: number; questionIds: string[] }; // ежедневный тест (закреплён за днём)
  tasks?: string[];        // побочные задания дня (закреплены за днём)
  tasksDone?: string[];    // id выполненных побочных заданий
  chest?: true;            // все три задания выполнены
  frozen?: true;           // день закрыт заморозкой или реваншем
  revenge?: true;          // день восстановлен реваншем
};

type Progress = {
  version: 2;
  updatedAt: number;
  topics: Record<string, { doneAt: number; best: number; lastReviewAt?: number }>;
  reviews: number;                       // успешные повторения
  perfectQuizzes: number;                // мини-тесты 3/3
  materialsOpened: Record<string, true>; // ключ `${topicId}:${index}`
  materialsV2?: true;                    // отметки по новому списку материалов (без флага — сбросить)
  notes: Record<string, string>;
  longNotes: Record<string, true>;       // темы, заметка к которым уже доходила до 50 символов
  exams: Record<string, { attempts: number; best: number; passedAt?: number; bestTimeSec?: number }>;
  days: Record<string, DayStats>;        // 'YYYY-MM-DD' (локальная дата)
  streak: {
    freezes: number;                     // 0..2
    freezeAwards: Record<string, true>;  // `${начало серии}:${отметка}` — заморозка за отметку уже выдана
    revengeUsed: Record<string, true>;   // дата пропущенного дня, по которому реванш уже использован
  };
  bestStreak: number;
  flags: { night?: true; early?: true; speedrun?: true; oldGuard?: true };
  openGood: number;                      // открытых вопросов с самооценкой «знала»
  achievements: Record<string, number>;  // id -> когда открыта
  rewards: Record<string, { claimedAt: number; issuedAt?: number }>;
  dailyGoal: number;
};
```

ID вопроса: `${topicId}:${index}` в массиве `quiz`. Ключ localStorage прежний (`nika-course:progress:v1`).

**Миграция v1 → v2** (`migrateV1toV2`, вызывается из `normalizeProgress` при загрузке и импорте):
`days[d] = { topics: activeDays[d], reviews: 0, materials: 0, perfectQuizzes: 0, notes: 0 }`,
`streak = { freezes: 0, freezeAwards: {}, revengeUsed: {} }`, `longNotes` — по уже написанным заметкам ≥50 символов.

XP **вычисляется** из прогресса, а не хранится (иначе двойные начисления при ретраях и импорте):
тема 50 (новая тема 80), мини-тест 3/3 +20, повторение +10, материал +5, первый проход босса +200,
финальный босс +500, ачивка +30; ежедневный тест сдан +40 за день, сдан на 5/5 (полный тест) ещё +20,
побочное задание +10, сундук +30, реванш +50. Уровень = `floor(xp / 250) + 1`.
Ранги по уровням: 1–2 Железо, 3–4 Бронза, 5–6 Серебро, 7–8 Золото, 9–11 Платина, 12–14 Алмаз,
15–18 Мастер, 19+ Грандмастер.

**Серия** (как в Duolingo). Активный день: за локальную дату пройдена хотя бы одна тема (новая или
повторение) **или** сдан ежедневный тест. Серия — подряд идущие дни, где день активный или `frozen`, до
сегодня; если сегодня ещё не активен — до вчера (до конца дня не обнуляется). Дневная цель «X/3 тем» =
`topics + reviews` за сегодня.

**Заморозки**: за каждые 7 дней серии (7, 14, 21, …) +1, на руках максимум 2; начисление идемпотентно
через `freezeAwards`. При загрузке (и при смене дня) пропущенные дни между последним днём серии и вчера
закрываются заморозками; если заморозок **меньше**, чем пропусков, — не тратить, серия сгорает.

**События**: день стал активным — короткая анимация «+1 к серии»; на 3, 7, 14, 30, 50, 100 днях —
полноэкранный экран празднования; сундук и реванш — тоже полноэкранные. Порядок: сначала празднования,
потом экраны ачивок, по одному за раз.

Чистые функции — в `src/logic/` (`streak.ts`, `daily.ts`, `migrate.ts`, `dates.ts`, `random.ts`), всё под тестами.
Общий пересчёт после каждого действия и раз в минуту — `applyDaily`: заморозки → квест дня → задания и
сундук → новые заморозки → лучшая серия; затем `applyAchievements`.

## 4. Ачивки

Список, условия и награды по умолчанию — в `achievements` в `content/roadmap.json`.
Ачивки с полем `block` (`block-py`, `block-sql`, …) открываются, когда пройдены все темы этого блока —
обрабатывать их одним общим правилом по полю `block`, а не отдельным кодом на каждую.
Проверка — одна чистая функция `evaluate(progress, content) → string[]` (id всех выполненных),
после каждого действия: новые id → запись в `achievements` + экран «Ачивка открыта».
Покрыть `evaluate`, подсчёт XP и серии unit-тестами (vitest) — это вся логика, где легко ошибиться.

Ачивки серии и ежедневных квестов (идут после `streak-7`):
- «Серия N дней» (`streak-3/7/14/30/50/100`) — по `bestStreak`, он обновляется при каждом пересчёте,
  поэтому ачивка не пропадает, когда серия сгорает.
- `dq-first` / `dq-10` / `dq-30` — число дней со сданным ежедневным тестом; `dq-flawless` — 5/5 на полном тесте.
- `dq-chest-7` — 7 сундуков (не обязательно подряд); `dq-perfect-week` — 7 сундуков подряд.
- `dq-weekend` — тест сдан в субботу и в следующее за ней воскресенье.
- `dq-old-guard` — в ежедневном тесте верный ответ по теме, пройденной 30+ дней назад (`flags.oldGuard`).
- `streak-freeze` — есть день, закрытый заморозкой (не реваншем); `streak-revenge` — есть день, восстановленный реваншем.
- `streak-phoenix` — в истории есть серия ≥7, после неё другая серия тоже дошла до 7.
- Ачивки «за один день» (`combo-5`, `combo-10`) читают `days[d].topics`.

## 5. Награды и «пульт мужа»

Этап 1 (localStorage): кнопка «Забрать» показывает экран-купон с названием награды и датой —
Ника показывает его мужу. Честная система, без сервера.

Этап 2 (Supabase):
- таблица `progress (user_id uuid pk, data jsonb, updated_at timestamptz)`;
- RLS: пользователь читает/пишет только свою строку; админ (`auth.uid()` мужа, задаётся в политике)
  читает все строки и может обновлять только `data->rewards->*->issuedAt` — проще через отдельную
  таблицу `reward_issues (user_id, achievement_id, issued_at)`, куда пишет только админ;
- таблица `reward_texts (achievement_id pk, text)` — пишет только админ;
- конфликт синхронизации: last-write-wins по `updatedAt`, но `topics`/`achievements`/`rewards` мержить
  объединением (ничего пройденного не теряется).
- Ключи Supabase в клиенте — только `anon key`, вся защита на RLS. `service_role` в репозиторий не класть.

Уведомление в Telegram при запросе награды — только через Supabase Edge Function (токен бота
нельзя держать во фронтенде статического сайта).

## 6. Этапы

1. Каркас: Vite+React+TS, HashRouter, загрузка `roadmap.json`, страницы Карта и Тема, мини-тесты, localStorage.
2. Геймификация: XP, ранги, серия, дневная цель, ачивки, тосты, купоны наград.
3. Боссы: симулятор собеса с таймером и открытыми вопросами.
4. Деплой: GitHub Actions → Pages, проверить hash-ссылки и `base`.
5. Ежедневные квесты и серия: `#/daily`, огонёк в шапке с панелью недели, заморозки, реванш, баннер
   «серия под угрозой», празднования, прогресс version 2 с миграцией.
6. (опционально) Supabase: вход по email, синхронизация, пульт мужа, Telegram-уведомления.

Каждый этап — отдельная ветка и PR, перед мержем `npm run build` и `npm test` зелёные.

## 7. Дизайн

Минимальный «курсовой» вид: светлый фон, одна акцентная краска, крупные карточки блоков, без эмодзи
в заголовках. Шрифты с кириллицей (например, Onest для текста, Unbounded для заголовков).
Должно нормально выглядеть на телефоне — Ника будет заходить с него.

## 8. Чего не делать

- Не генерировать новые тестовые вопросы без проверки человеком: неверный «правильный» ответ хуже отсутствия вопроса.
- Не хранить секреты в репозитории и в клиентском коде.
- Не тянуть тяжёлые зависимости ради мелочей (анимации, иконки).
