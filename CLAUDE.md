# Дата-квест Ники — спецификация для Claude Code

Персональный мини-курс для Ники (Python backend → Data Engineer): дорожная карта, материалы,
мини-тесты, симулятор техсобеса, геймификация с реальными наградами от мужа.
Хостинг — GitHub Pages, сайт должен работать без запущенного компьютера.

Контент курса уже собран в `content/roadmap.json`. Не переписывай его — только читай и расширяй.

---

## 1. Стек (решение принято, не менять без причины)

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite + React + TypeScript | статическая сборка в `dist/`, без сервера |
| Роутинг | `HashRouter` (react-router) | GitHub Pages не умеет SPA-фолбэк, hash-роуты работают без 404.html |
| Стили | обычный CSS / CSS Modules, без UI-кита | «типичный курс», минимальный дизайн |
| Контент | `content/roadmap.json`, импорт на этапе сборки | правится через PR, без админки |
| Прогресс (этап 1) | `localStorage` + экспорт/импорт JSON | ноль инфраструктуры |
| Прогресс (этап 2) | Supabase (free tier): Auth по email-ссылке + таблица `progress` | синхронизация между устройствами и «пульт мужа» |
| Деплой | GitHub Actions → `actions/deploy-pages` | push в main = обновление сайта |

`vite.config.ts`: `base: '/<имя-репозитория>/'`.

## 2. Страницы

- `#/` — **Карта**. Сверху статус-бар: ранг, уровень, полоска XP, серия дней, «сегодня X/3 тем».
  Карточка «Продолжить» (следующая непройденная тема) и «На повторение» (темы, пройденные ≥5 дней назад).
  Ниже 7 больших блоков (порядок — это и есть последовательность обучения): название, описание,
  метка «повторение»/«новое», прогресс-бар, список тем со статусом.
- `#/topic/:id` — **Тема**: «что повторить / что изучить» (`recap`), материалы (`materials`, клик = отметка
  «открыто»), личные заметки (textarea, автосохранение), мини-тест из 3 вопросов.
  Тема засчитывается при ≥2/3 правильных. Повторная сдача после 3+ дней = «повторение» (+XP).
- `#/exam` — **Боссы (симулятор собеседования)**, список в `exams`. Прохождение: N вопросов с выбором
  из пула блоков (случайно, без повторов), видимый таймер, затем открытые вопросы из `open_questions`
  с самооценкой: «показать эталон» → «знала / частично / не знала». Сдано, если тестовая часть ≥80%.
  `final` заблокирован, пока не сданы остальные три.
- `#/achievements` — **Ачивки**: сетка значков (закрытые — серые с условием), у открытых дата и награда
  с кнопкой «Забрать». Статусы награды: доступна → запрошена → выдана.
- `#/settings` — дневная цель (по умолчанию 3 темы), экспорт/импорт прогресса JSON, сброс.
- (этап 2) `#/admin` — **Пульт мужа**: её XP, темы, история боссов, запрошенные награды с кнопкой «Выдано»,
  редактирование текстов наград.

Варианты ответов в тестах **перемешивать при каждом показе**: в JSON правильный ответ всегда первый (`options[0]`).
После проверки показывать `explain` к каждому вопросу.

## 3. Модель прогресса

```ts
type Progress = {
  version: 1;
  updatedAt: number;
  topics: Record<string, { doneAt: number; best: number; lastReviewAt?: number }>;
  reviews: number;                       // успешные повторения
  perfectQuizzes: number;                // мини-тесты 3/3
  materialsOpened: Record<string, true>; // ключ `${topicId}:${index}`
  notes: Record<string, string>;
  exams: Record<string, { attempts: number; best: number; passedAt?: number; bestTimeSec?: number }>;
  activeDays: Record<string, number>;    // 'YYYY-MM-DD' (локальная дата) -> тем пройдено за день
  bestStreak: number;
  flags: { night?: true; early?: true; speedrun?: true };
  openGood: number;                      // открытых вопросов с самооценкой «знала»
  achievements: Record<string, number>;  // id -> когда открыта
  rewards: Record<string, { claimedAt: number; issuedAt?: number }>;
  dailyGoal: number;
};
```

XP **вычисляется** из прогресса, а не хранится (иначе двойные начисления при ретраях и импорте):
тема 50 (новая тема 80), мини-тест 3/3 +20, повторение +10, материал +5, первый проход босса +200,
финальный босс +500, ачивка +30. Уровень = `floor(xp / 250) + 1`.
Ранги по уровням: 1–2 Железо, 3–4 Бронза, 5–6 Серебро, 7–8 Золото, 9–11 Платина, 12–14 Алмаз,
15–18 Мастер, 19+ Грандмастер.

Серия: подряд идущие дни в `activeDays` до сегодня (или до вчера, если сегодня ещё пусто).

## 4. Ачивки

Список, условия и награды по умолчанию — в `achievements` в `content/roadmap.json`.
Проверка — одна чистая функция `evaluate(progress, content) → string[]` (id всех выполненных),
после каждого действия: новые id → запись в `achievements` + тост «Ачивка открыта».
Покрыть `evaluate`, подсчёт XP и серии unit-тестами (vitest) — это вся логика, где легко ошибиться.

## 5. Награды и «пульт мужа»

Этап 1 (localStorage): кнопка «Забрать» показывает экран-купон с названием награды и датой —
Ника показывает его мужу. Честная система, без сервера.

Этап 2 (Supabase):
- таблица `progress (user_id uuid pk, data jsonb, updated_at timestamptz)`;
- RLS: пользователь читает/пишет только свою строку; админ (`auth.uid()` мужа, задаётся в политике)
  читает все строки и может обновлять только `data->rewards->*->issuedAt` — проще через отдельную
  таблицу `reward_issues (user_id, achievement_id, issued_at)`, куда пишет только админ;
- таблица `reward_texts (achievement_id pk, text)` — пишет только админ;
- конфликт синхронизации: last-write-wins по `updatedAt`, но `topics`/`achievements`/`rewards` мержить
  объединением (ничего пройденного не теряется).
- Ключи Supabase в клиенте — только `anon key`, вся защита на RLS. `service_role` в репозиторий не класть.

Уведомление в Telegram при запросе награды — только через Supabase Edge Function (токен бота
нельзя держать во фронтенде статического сайта).

## 6. Этапы

1. Каркас: Vite+React+TS, HashRouter, загрузка `roadmap.json`, страницы Карта и Тема, мини-тесты, localStorage.
2. Геймификация: XP, ранги, серия, дневная цель, ачивки, тосты, купоны наград.
3. Боссы: симулятор собеса с таймером и открытыми вопросами.
4. Деплой: GitHub Actions → Pages, проверить hash-ссылки и `base`.
5. (опционально) Supabase: вход по email, синхронизация, пульт мужа, Telegram-уведомления.

Каждый этап — отдельная ветка и PR, перед мержем `npm run build` и `npm test` зелёные.

## 7. Дизайн

Минимальный «курсовой» вид: светлый фон, одна акцентная краска, крупные карточки блоков, без эмодзи
в заголовках. Шрифты с кириллицей (например, Onest для текста, Unbounded для заголовков).
Должно нормально выглядеть на телефоне — Ника будет заходить с него.

## 8. Чего не делать

- Не генерировать новые тестовые вопросы без проверки человеком: неверный «правильный» ответ хуже отсутствия вопроса.
- Не хранить секреты в репозитории и в клиентском коде.
- Не тянуть тяжёлые зависимости ради мелочей (анимации, иконки).
